2. DATA FLOW DIAGRAM
================================================================================

   Step 1: Fetch Knit Orders
   -------------------------
   fabric_forecast_integrated()
       |
       +--> _get_knit_orders_data()
               |
               +--> fetch_from_efab('api/knitorder/list')
                       |
                       +--> External eFab API
                       |
                       +--> Returns: {orders: [...]}
               |
               +--> Transform data:
                       - Extract style, customer, quantities
                       - Calculate balance_lbs (qty_ordered - qty_received)
                       - Calculate completion_percentage
               |
               +--> Return: {orders: [{id, style, balance_lbs, ...}]}


   Step 2: Fetch Inventory Pipeline
   ---------------------------------
   fabric_forecast_integrated()
       |
       +--> _get_inventory_pipeline_data()
               |
               +--> Returns STUB: {
                       pipeline: {
                           G00: {total_on_hand: 0, items: []},
                           G02: {total_on_hand: 0, items: []},
                           I01: {total_on_hand: 0, items: []},
                           F01: {total_on_hand: 0, items: []}
                       }
                   }


   Step 3: Fetch Yarn Intelligence (Optional)
   -------------------------------------------
   fabric_forecast_integrated()
       |
       +--> _get_yarn_intelligence_data()
               |
               +--> fetch_from_efab('api/yarn/active')
                       |
                       +--> External eFab API
                       |
                       +--> Returns: [{yarn_data}]
               |
               +--> Transform data:
                       - Calculate theoretical_balance
                       - Calculate planning_balance
               |
               +--> Return: {yarn: [{yarn_id, planning_balance, ...}]}


   Step 4: Build Fabric Allocations
   ---------------------------------
   fabric_forecast_integrated()
       |
       +--> _build_fabric_allocations(knit_orders)
               |
               +--> For each active order:
                       - Extract fabric_id (first 4 digits of style)
                       - Get balance_lbs
                       - Convert to yards: balance_lbs * 5.0
                       - Aggregate by fabric_id
               |
               +--> Return: {fabric_id: total_yards_allocated}


   Step 5: Process Inventory Pipeline
   -----------------------------------
   fabric_forecast_integrated()
       |
       +--> _process_inventory_pipeline(pipeline)
               |
               +--> Aggregate inventory by stage:
                       - G00: Greige received
                       - G02: Greige in process
                       - I01: Finished goods
                       - F01: Shipped
               |
               +--> Return: {ALL_FABRICS: {G00: yards, G02: yards, ...}}


   Step 6: Generate Forecast Items
   --------------------------------
   fabric_forecast_integrated()
       |
       +--> _generate_forecast_items(knit_orders, allocations, inventory)
               |
               +--> Fetch fabric specs from Turso:
               |       SELECT style, yds_per_lb, fabric_type
               |       FROM fabric_specs
               |
               +--> For each order (top 20):
                       |
                       +--> Get fabric specs from Turso
                       |       - yds_per_lb (fallback: 3.0)
                       |       - fabric_type
                       |
                       +--> Calculate forecasted_yards:
                       |       balance_lbs * yds_per_lb
                       |
                       +--> Get inventory levels:
                       |       - current_inventory = (I01 + F01) / num_orders
                       |       - on_order = (G00 + G02) / num_orders
                       |
                       +--> Calculate net position:
                       |       net_position = current_inventory + on_order
                       |                      - allocated - forecasted_yards
                       |       net_requirement = -net_position
                       |
                       +--> Determine priority:
                               if net_requirement > forecasted * 0.6:
                                   CRITICAL (2 weeks)
                               elif net_requirement > 0:
                                   HIGH (4 weeks)
                               else:
                                   NORMAL (6 weeks)
               |
               +--> Return: [{style, fabric_type, forecasted_yards, ...}]


   Step 7: Calculate Summary
   -------------------------
   fabric_forecast_integrated()
       |
       +--> _calculate_fabric_summary(forecast_items)
               |
               +--> Calculate:
                       - total_yards_forecasted
                       - total_net_requirement
                       - critical_items (count)
                       - high_priority_items (count)
                       - total_estimated_cost
                       - timeline_alert (boolean)
                       - total_styles (unique count)
                       - fabric_types_count (unique count)
               |
               +--> Return: {summary metrics}


   Step 8: Return Response
   -----------------------
   fabric_forecast_integrated()
       |
       +--> Build response:
               {
                   status: "success",
                   forecast_items: [...],
                   fabric_forecast: [...],  // Dashboard compatibility
                   summary: {...},
                   data_sources: {...},
                   timestamp: "..."
               }
       |
       +--> Return: (response, 200)


3. ERROR HANDLING FLOW
================================================================================

   Error Scenario 1: eFab API Unavailable (Knit Orders)
   -----------------------------------------------------
   fabric_forecast_integrated()
       |
       +--> _get_knit_orders_data()
               |
               +--> fetch_from_efab('api/knitorder/list')
                       |
                       +--> TIMEOUT / CONNECTION ERROR
                       |
                       +--> Return: None
               |
               +--> Return: None
       |
       +--> Check: if knit_orders_response is None:
               |
               +--> Return ERROR response:
                       {
                           status: "error",
                           message: "eFab API unavailable - Cannot load production orders",
                           forecast_items: [],
                           fabric_forecast: [],
                           summary: {all zeros},
                           timestamp: "..."
                       }
                       HTTP 500


   Error Scenario 2: No Knit Orders Available
   -------------------------------------------
   fabric_forecast_integrated()
       |
       +--> _get_knit_orders_data()
               |
               +--> fetch_from_efab('api/knitorder/list')
                       |
                       +--> Returns: []
               |
               +--> Return: {orders: []}
       |
       +--> Check: if len(knit_orders) == 0:
               |
               +--> Return NO DATA response:
                       {
                           status: "no_data",
                           message: "No knit orders available for fabric forecast",
                           forecast_items: [],
                           fabric_forecast: [],
                           summary: {all zeros},
                           timestamp: "..."
                       }
                       HTTP 200


   Error Scenario 3: Inventory Pipeline Unavailable (Graceful)
   ------------------------------------------------------------
   fabric_forecast_integrated()
       |
       +--> _get_inventory_pipeline_data()
               |
               +--> Returns: {pipeline: {...}}  (currently stub)
       |
       +--> Check: if inventory_response is None:
               |
               +--> pipeline = {}
               |
               +--> CONTINUE (not critical)


   Error Scenario 4: Yarn Intelligence Unavailable (Graceful)
   -----------------------------------------------------------
   fabric_forecast_integrated()
       |
       +--> _get_yarn_intelligence_data()
               |
               +--> fetch_from_efab('api/yarn/active')
                       |
                       +--> TIMEOUT / ERROR
                       |

       |
       +--> yarn_data = []
       |
       +--> CONTINUE (optional data)

       +--> Try:

       |
       +--> Except:
               |
               +--> Log error
               |
               +--> fabric_specs_lookup = {}
               |
               +--> Use fallback: yds_per_lb = 3.0
       |
       +--> CONTINUE with defaults


   Error Scenario 6: Internal Exception (Catch-All)

               {all processing steps}
       |

               |

                           status: "error",
                           message: "Internal error: ...",

       - style (TEXT)

       - width (REAL)

   Query:
       SELECT style, yds_per_lb, gsm, width, fabric_type
       FROM fabric_specs

   Usage:

           |
           +--> Fetch all fabric specs at once
           |
           +--> Build lookup dict: {style: {yds_per_lb, fabric_type}}
           |
           +--> For each order:
                   specs = fabric_specs_lookup.get(style)
                   yds_per_lb = specs.get('yds_per_lb', 3.0)  # Fallback
                   fabric_type = specs.get('fabric_type', 'Unknown')

   ----------------------------
   Request:
       GET https://efab.bkiapps.com/api/yarn/active

       [
           {
               desc_number: string,

       - Calculate: planning_balance = theoretical_balance + onorder + allocated


7. PRIORITY DETERMINATION ALGORITHM
================================================================================

   Input:
       - forecasted_yards: int
       - net_requirement: int

   Algorithm:
       IF net_requirement > forecasted_yards * 0.6:
           priority = "CRITICAL"
           status = "URGENT_ORDER"
           lead_time_weeks = 2

       ELSE IF net_requirement > 0:
           priority = "HIGH"
           status = "ORDER_SOON"
           lead_time_weeks = 4

       ELSE:
           priority = "NORMAL"
           status = "ADEQUATE"
           lead_time_weeks = 6

   Example Calculations:
       forecasted_yards = 10000

       Case 1: net_requirement = 7000
           7000 > 10000 * 0.6 (6000) → CRITICAL

       Case 2: net_requirement = 5000
           5000 > 0 → HIGH

       Case 3: net_requirement = -2000
           -2000 <= 0 → NORMAL


8. NET POSITION CALCULATION
================================================================================

   Formula:
       net_position = current_inventory + on_order - allocated - forecasted_yards
       net_requirement = -net_position (if negative)

   Components:
       current_inventory = (I01_yards + F01_yards) / num_orders
       on_order = (G00_yards + G02_yards) / num_orders
       allocated = fabric_allocations[fabric_id]
       forecasted_yards = balance_lbs * yds_per_lb

   Example:
       current_inventory = 5000 yards
       on_order = 3000 yards
       allocated = 2000 yards
       forecasted_yards = 15000 yards

       net_position = 5000 + 3000 - 2000 - 15000
                    = -9000 yards

       net_requirement = -(-9000) = 9000 yards
       → Need to order 9000 yards


9. RESPONSE TIME BREAKDOWN
================================================================================

   Total Response Time: 600-1200ms (typical)

   +----------------------------+------------+----------+
   | Operation                  | Time (ms)  | % Total  |
   +----------------------------+------------+----------+
   | eFab API: Knit Orders      | 300-500    | 40%      |
   | eFab API: Yarn Data        | 200-400    | 30%      |
   | Turso DB: Fabric Specs     | 50-100     | 8%       |
   | Build Allocations          | 10-20      | 2%       |
   | Process Inventory          | 5-10       | 1%       |
   | Generate Forecast Items    | 30-60      | 5%       |
   | Calculate Summary          | 5-10       | 1%       |
   | JSON Serialization         | 10-20      | 2%       |
   | Network Overhead           | 50-100     | 8%       |
   +----------------------------+------------+----------+

   Bottleneck: External eFab API calls (70% of total time)

   Optimization Opportunities:
       1. Cache eFab responses (5-10 min TTL)
       2. Parallel API calls to eFab
       3. Cache Turso fabric specs (1 hour TTL)
